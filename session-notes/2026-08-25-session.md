## Boiler automation logic

- **ON** — triggers immediately on `binary_sensor.hive_trv_*_heat_required` going `on`
- **OFF** — triggers on `heat_required` going `off`, checks all clear, waits 3 minutes, re-checks, turns off
- **Spurious guard** — intercepts `zigbee2mqtt/Boiler Switch` MQTT messages with `state:ON` and no TRV demand, immediately publishes `OFF` back
- **Monitor** — logs every switch state change with `context_id`, `user_id`, `parent_id`
- **MQTT monitor** — logs raw Z2M payloads including bridge state

## Known issues investigated

### Boiler turning on randomly
- **Root cause found**: Sonoff ZBMINIR2 was publishing spurious `state:ON` MQTT messages
- `inching_control` was investigated — confirmed DISABLED in firmware
- `external_trigger_mode` set to `following(off)` — S1/S2 unused
- `power_on_behavior` set to `off`
- Spurious guard automation now intercepts at MQTT level before HA processes it
- Z2M polls device every ~30 min which causes state republish — spurious guard handles this

### Boiler OFF not working
- **Root cause**: `time_pattern: /2` watchdog + `mode:restart` = automation restarted every 2 min, 3 min delay never completed
- **Fix**: removed time_pattern, now triggers only on `heat_required` state changes

## Dashboard views

### Heating view
- Boiler tile (ON/OFF, toggleable)
- Global mode buttons (Manual / Schedule / Eco / Off) with active state highlight
- Living room mushroom climate card + TV/Bay/Dining chip indicators
- Individual room cards with flame badge + per-room boost controls
- Each room boost: temp input (1–32°C) + duration slider (10–120 min) + Boost/Cancel buttons

### TRV Settings view
- One entities card per TRV with all settings:
  programme mode, keypad lock, window detection, calibration offset,
  max temp, orientation, display direction, adaptation run, heat required, preheat

### Diagnostics view
- Boiler tile
- Heating demand logbook (all 11 TRVs + boiler switch)
- Boiler on/off history graph (24h)
- TRV heat demand history graph (24h)
- Current demand summary card
- Per-TRV demand grid (temp → target, demand %)
- Battery levels

### Schedule view
- `custom:trv-schedule-card` — native Lovelace card
- Room selector, Mon–Sun tabs, 1–6 slots per day
- Copy day to other days, copy week to other rooms
- Writes directly to TRV firmware via mqtt/publish
- Sets programming_operation_mode to schedule after writing
